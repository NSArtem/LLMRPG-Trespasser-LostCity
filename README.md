# Репозиторий непрерывной НРИ-кампании

Этот репозиторий хранит каноническое состояние кампании для ведения через
ChatGPT и Git. Рабочие файлы находятся прямо в корне, поэтому их удобно читать
человеку и подключённой модели. Название, система и текущая точка продолжения
указаны в [CURRENT.md](CURRENT.md).

## Модель данных

```text
scene → journal entry → checkpoint
```

- **Scene** (`scene-NNNN`) — непрерывная игровая ситуация.
- **Journal entry** (`journal.entry-NNNN`) — append-only запись нескольких
  связанных игровых отрезков.
- **Checkpoint** (`cp-NNNN`) — атомарно применённое состояние репозитория.

Границы сцены, журнала, чата и календарной встречи независимы друг от друга.
Git-коммит фиксирует применённый checkpoint.

## Где что хранится

- [CURRENT.md](CURRENT.md) — компактный актуальный снимок.
- [MANIFEST.md](MANIFEST.md) — карта минимальной загрузки контекста.
- `party/`, `npcs/`, `locations/` — актуальные состояния сущностей.
- `campaign/` — основы, факты, хронология, часы и открытые линии.
- `rules/` — приоритет источников, домашние правила и принятые решения.
- `gm/` — закрытые сведения ведущего и изменения исходного материала.
- `journal/` — компактная append-only история.
- `checkpoints/` — машиночитаемая цепочка сохранений.
- `templates/` — неизменяемое состояние до кампании для полного сброса.

## Подготовка новой кампании

После сброса `CURRENT.md` имеет статус `preparation`, а применённых checkpoint,
активных сцен и журналов нет.

1. Выберите систему, редакцию, сеттинг или приключение.
2. Заполните [основы кампании](campaign/premises.md).
3. Создайте персонажей из `party/character-template.md`.
4. Заполните группу, стартовые сущности и `CURRENT.md`.
5. Создайте baseline `cp-0001`, `journal.entry-0001` и `scene-0001`.
6. Переключите `campaign_status` на `active`.
7. Запустите `python3 scripts/validate_repo.py`.

Специфические для выбранной системы поля можно добавлять в универсальные
файлы и шаблоны.

## Практический цикл

```text
открыть чат
→ прочитать MANIFEST и CURRENT
→ сверить текущую сцену
→ продолжать игру
→ сформировать checkpoint-пакет
→ применить его локально
→ проверить diff и валидатор
→ commit
```

Не вычисляйте актуальные здоровье, ресурсы или местоположение перечитыванием
всей истории: они должны быть перенесены в `CURRENT.md` и профильные файлы.

## Полный сброс

Чтобы вернуть репозиторий в системно-нейтральное состояние до кампании:

```bash
scripts/reset_campaign.sh
```

Скрипт покажет точный список заменяемых путей и потребует ввести `RESET`.
Неинтерактивный вариант:

```bash
scripts/reset_campaign.sh --yes
```

Сброс безвозвратно заменяет только пути, перечисленные в
`templates/reset-paths.txt`. Он не затрагивает `.git/`, инфраструктурные
документы, скрипты, PDF и посторонние корневые файлы. Источник восстановления
находится в `templates/`.

Перед сбросом рекомендуется проверить `git status` и сохранить нужную историю
коммитом или отдельной резервной копией.

## Источники и приложения

Официальный текст правил, приключения и другие крупные исходники храните в
ChatGPT Project как attachments, если это допускает лицензия, а не в Git.
Репозиторий отвечает на вопрос «что истинно сейчас», а исходный материал —
«как всё выглядело до изменений кампании».

При конфликте используйте [правила приоритета](rules/precedence.md). Не
раскрывайте игрокам содержимое `gm/` напрямую.

## Проверка

```bash
python3 scripts/validate_repo.py
```

Валидатор ничего не изменяет. Он принимает как чистое состояние
`preparation`, так и активную кампанию с непрерывной цепочкой checkpoint.
